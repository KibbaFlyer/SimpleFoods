# Open Food Facts runtime cache and bounded country Sync

Implemented in `MealTracker/Sources/MealTrackerOpenFoodFacts/OFFLibrary.swift`; mocked tests are in `MealTracker/Tests/MealTrackerOpenFoodFactsTests`. Integration also includes the private overlay/diary test in the storage test target.

## API and Sync meaning

OFFLibrary is an actor with init(databaseURL:transport:clock:userAgent:sleep:), cached(barcode:), cachedProducts(), local-first lookup(barcode:language:), explicit refresh(barcode:language:), tracked-only sync(), and sync(markets:[.germany,.sweden],pageSize:5,pagesPerMarket:3,maxProductFetches:10). Construction/cache reads never contact OFF. Transport and clock/sleeper are injectable; production sleep enforces request pacing. All network operations require explicit lookup/refresh/Sync actions.

Country Sync first refreshes every tracked source code, preserving existing behavior. It then performs bounded discovery for the chosen sales markets (DE -> germany/en:germany; SE -> sweden/en:sweden). Discovery searches metadata through documented /api/v2/search with countries_tags_en, sort_by=last_modified_t, page/page_size and code,last_modified_t,rev,countries_tags fields. V3 has no structured search endpoint; full product fetches use current /api/v3/product/{code}. Returned checksummed barcodes, requested country membership, finite integer revision and nonfuture modification timestamps are validated. New/changed records trigger product GETs; matching cached versions need no second detail fetch. UPC-A/zero-prefixed EAN-13 equivalents are deduplicated across pages and markets.

Every run checks newest page 1 plus overlapping cursor pages. Successful batches persist next cursor/page size/success time; changing page size restarts the cursor safely. pagesPerMarket is clamped to 3…4 to reserve overlap while still advancing; pageSize to 1…20; additional discovery product GET budget to 1…50 (default10). Budget is shared fairly between selected markets (default5 each), with unused share available to later markets. Existing tracked refreshes are separate from this additional-discovery budget and may take longer for a large personal cache. Every request has timeouts; no background loop or automatic retry is scheduled.

A page/product/network/429/invalid-record/ambiguous short-page/budget failure preserves the prior market cursor and successful checkpoint. Successfully imported source records remain available, and the next explicit run rechecks the retained batch. A response claiming more products than a short page actually returns is treated as incomplete. Checkpoints are successful bounded batch times, NOT global change watermarks. Search pagination is not snapshot isolated: moving records/ties/index lag can still cause omissions despite head/overlap rescans. No claim of complete country coverage or all-country freshness is made. Reaching the end wraps tail traversal; hasMore indicates remaining pages when known. There is no unbounded full OFF download or invented modification filter.

OFFSyncReport retains items/failedCount and adds discovery:[OFFDiscoveryResult], isComplete. Each market result exposes market/completed/hasMore/pagesFetched/importedCount/refreshedCount/nextPage/checkpointDate/error. completed/isComplete describe bounded work only, never country completeness. UI should surface partial/budget/remaining-page status and use community/unverified labels. Per-market refreshedCount counts additional discovery updates; tracked refresh outcomes are in items.

## Source/private separation and safeguards

The dedicated schema-version3 cache owns immutable raw revisions and current pointers plus market traversal state, and migrates older version1/2 caches. It rejects newer schemas. Whole-Sync serialization rejects concurrent network mutations; cached reads remain available. Source raw bytes/revision are retained. CatalogueFood/profile revisions are raw-response SHA256, independent of numeric OFF revision. Last attempt, last successful check, immutable retrieval time and upstream modification time are separate. Failed/stale/future/malformed detail results do not advance freshness. No-change checks do not append revisions. Meal snapshots are never rewritten.

Only this OFF cache is written: PersonalLibrary, private overlays, full nutrition-profile overrides, custom names, and saved meals are never read or modified by this module. FoodID remains stable for the same cached barcode; the app resolves its stored private overlay on top of refreshed source data. Full-profile overrides continue to replace the source profile as an explicit user choice; the OFF source update remains available separately. No name-based merge occurs.

Cache directories and SQLite files/sidecars receive complete protection/exclusion on iOS; macOS only the dedicated database file is marked excluded, avoiding mutations of shared temporary parent directories. Tests use dedicated UUID directories. Default transport is ephemeral with no cookies or HTTP cache, reloadIgnoringLocalCacheData, 30s request/45s resource timeout, and 2MB response rejection. Custom User-Agent identifies the actual repository. Product request starts are at least4.1s apart (15/minute); search starts at least6.1s apart (10/minute). Full valid Retry-After deadlines are honored; default is60s, with no automatic retry loop. Read data stays local; no photos/uploads/private payloads.

Nutrition mapping stays conservative: current v3 aggregate must be as_sold, explicit100g/100ml, packaging source, matching source_per, direct supported-unit value and no modifier. Computed values are ignored. Legacy modifiers such as '<' now remain unknown rather than becoming exact values. Legacy unit/basis ambiguity is rejected, including volume packages labelled with generic100g. No energy recomputation, kJ conversion, sodium/salt conversion, density, serving conversion or carbohydrate-definition inference. Unknowns never become zero. Unsupported records remain source-only with names/brands/raw metadata. Countries use explicit ISO mappings; manufacturing places are not manufacturing-country evidence.

## Official evidence reviewed 11 October 2026

- [API introduction/current versions and rate limits](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/): v3 current, v2 deprecated but structured search available only in v2;15 product GET/minute and10 search/minute. More than a few hundred products requires a separate acquisition strategy. No bulk acquisition is implemented here.
- [Official filtered Search Products](https://openfoodfacts.github.io/documentation/docs/Product-Opener/v2/search/get-search/): country taxonomy filters, last_modified_t sorting, field selection, page/page_size and returned count. No documented safe global modification watermark predicate was found, so this implementation uses bounded overlap pagination honestly.
- [Official search tutorial](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/tutorial-off-api/): sort_by=last_modified_t examples.
- [Current v3 product GET/schema](https://openfoodfacts.github.io/documentation/docs/Product-Opener/v3/products/get-api-v3-product-code/): raw source metadata, current nutrition schema and field filters.
- [Product metadata schema](https://openfoodfacts.github.io/documentation/docs/Product-Opener/schemas/schemas/product_metadata/): primary modification time and numeric source edit revision are independent of local successful-check times.
