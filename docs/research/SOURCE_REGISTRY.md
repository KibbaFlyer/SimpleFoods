## Confirmed terms and interpretation boundaries

[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) permits adaptation and sharing with credit, licence link, and change indication; no extra legal/technical restrictions that prevent licensed uses. This supports BLS-derived packs; it does not establish that every separately linked website asset has that licence. Retain source/copyright notices supplied with the actual dataset.

Under [ODbL 1.0 §§4.2–4.7](https://opendatacommons.org/licenses/odbl/1-0/), publicly used derivative databases require share-alike, notices and a machine-readable derivative or complete alteration/method offer. Collective databases have a limited exception; their OFF component remains licensed. Offline distribution has no exemption. Small size alone does not establish insubstantial extraction, especially with repeated systematic extraction. Engineering choice: publish an unrestricted OFF-only derivative package and recipe/configuration inputs when release is approved, with no private diary data. Review app-store technical restrictions and parallel distribution. Physical file separation alone does not prove a collective database, and a combined index may itself require review. This decision does not assert compatibility of BLS, SLV and OFF combinations.

[OFF field documentation](https://github.com/openfoodfacts/openfoodfacts-server/blob/main/html/data-fields.txt) distinguishes `countries` (sold in), `origins` (ingredient origins), and `manufacturing_places` (manufactured/transformed). Normalize market tags separately; never infer origin from Swedish/German market, language, barcode prefix, brand, or hostname.

## Registry and release gates for D02

Require source ID; upstream dataset version; software API version separately; retrieved timestamp; access URL; SHA-256; applicable licence URL/version and dated evidence reference; attribution; transform ledger; evidence reviewer; rights status; acquisition status; release decision; distribution/offer URL where required. Unknown required evidence blocks production packaging, rather than defaulting to approved.

Use independent gates: `research_allowed`, `raw_acquired`, `schema_verified`, `rights_reviewed`, `release_allowed`. BLS has a positive licence finding but no raw/schema gate passed. SLV/OFF may be researched and adapters developed behind fixtures; release remains false. Synthetic development is allowed; synthetic production is false. Require a human-reviewed release decision with evidence, not arbitrary booleans in a pack.

A public pack build accepts only an explicit allowlist of acquired public snapshots; it must never read application-private directories, personal overlays, diary databases, backups, Health samples, private indexes or logs. Cross-source links must preserve provenance and cannot erase licence obligations. Private calculations do not automatically authorize public redistribution of those calculated databases.
